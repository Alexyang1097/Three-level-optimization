# 三种训练方法的实现核验

日期：2026-10-15。

范围：当前工作区的 Uniform、Staged、Primal–Dual 训练与评估实现，以及磁盘 `runs/main_budget_4000` 的已保存实验。本文是对公式、程序行为和部分结果复现的核验，不是所有配置下正确性的证明。本轮没有修改训练或评估算法，也没有为了得到预期的方法排名而调整超参数。

## 1. 判断

**本轮未发现导致三方法比较偏向 Uniform 的核心公式或流程错误。** 当前实现与研究笔记第 23–25 页的主要神经实验协议一致，运行检查也支持目标、梯度截断、数据配对和评估逻辑正确。

但不能据此称完整实验已经充分验证：当前训练代码没有构建配置中声明的验证集，主实验没有固定惩罚组，也没有逐步 dual 日志。另一个值得优先检查的现象是，三种模型的第一步测试误差均高于一个不使用 demonstrations 的解析分布基线，提示应进一步检查上下文任务的学习程度。

研究笔记把神经实验写成待检验的设计，没有假设数值结果必须显示 Primal–Dual 或 Staged 胜出。其非凸 Transformer 与 Adam 实验也不直接享有确定性参考算法的全部理论保证。

## 2. 对照文档的静态核验

| 项目 | 实现与核验结果 |
|---|---|
| 任务与输入 | 每个 prompt 独立任务参数，同一任务的 demonstrations 与 query；固定训练池和固定示例数量；参数分布与 ID/OOD 输入分布符合第 7.1、7.3 节。 |
| 网络与损失 | 三块、两头、宽度 64、MLP 256、零 dropout；query-only teacher forcing；只计算有效输出维度；固定训练目标能量归一化。 |
| 累计目标 | `f1=e1`，`f2=(e1+e2)/2`，`f3=(e1+e2+e3)/3`。 |
| Uniform | 全程最小化 `f3`，4000 次模型更新；不是最小化 `f1+f2+f3`。 |
| Staged | 依次最小化 `f1、f2、f3`，1000、1500、1500 次；每阶段重建 Adam。 |
| Primal–Dual | 第一阶段取最小已测 `f1`；按 `+0.02` 构建 `b1`；第二阶段按可行性与 `f2` 选择参考点；按 `+0.02` 构建 `b2`；最终在可行已测点中选择最小 `f3`。 |
| Dual 更新 | `lambda_new=[(1-omega)lambda_old+(omega/nu)(f_hat-b)]_+`，`nu=0.02、omega=0.05`；使用 minibatch 损失，更新乘子时对约束 detach。 |
| Primal 梯度 | 对 `fk + sum(lambda_new_i * fi)` 求导，乘子固定；省略的阈值项和 dual 正则项在固定乘子下不改变模型梯度。 |
| 更新计数 | 每次模型更新一次 backward；dual 的标量运算没有额外计入 backward。 |
| 模型选择 | 基线按最小全池训练 `f3` 选择，Primal–Dual 加可行性条件；符合第 7.2 节，不能擅自改成按测试集选择。 |

Staged 与 Primal–Dual 仍有一个协议层面的差别：前者按当前阶段末状态继续，后者会恢复选中的可行参考 checkpoint。研究笔记没有要求基线采用完全相同的参考恢复过程。因此，“Staged 对比 Primal–Dual”在一般配置下不必等同于“只改乘子、其他一切完全相同”的因果消融。在本次三个种子的已保存记录中，所选阶段参考状态对应阶段末指标，这个差别没有表现为记录中的阶段切换损失跳变。

## 3. 实际运行检查

### 3.1 小规模训练审计

使用 CPU、固定种子、32 条训练记录、batch size 8，三个阶段各 4 次更新，Uniform 共 12 次更新。对真实训练函数进行插桩，共检查 36 次更新的实际目标导数。

- 三种方法初始模型参数的哈希相同。
- 12 次 minibatch 的内容和顺序在三方法间完全一致，包括跨 epoch 和阶段切换的位置。
- 三种方法的归一化尺度一致。
- Staged 与 Primal–Dual 的第一阶段末模型参数完全一致。
- 实际目标对 `e1、e2、e3` 的导数，符合各阶段的目标与乘子系数；未发现意外对乘子反向传播。
- Uniform 的 Adam 构建一次，两个分阶段方法均构建三次。
- 每种方法记录 12 次 backward、12 次模型更新和 96 个训练 prompt；dual 没有扣减模型更新机会。
- 参考阈值与最终模型选择满足文档规则。

### 3.2 因果掩码、padding 与 query 对齐

用实际三块 Transformer 检查：

- 同一条记录放在变长 padded batch 中或单独推断，预测近似一致。
- 改动 query 的未来真实中间答案，不改变之前位置的预测，未发现未来目标泄漏。
- teacher-forced 的前两步输出，与仅输入相应合法前缀的独立前向结果近似一致。

这些检查覆盖模型读出位置、因果掩码和变长 padding 的关键行为，但不是全部硬件与输入长度下的穷尽验证。

### 3.3 已保存实验核验

对三个方法、三个种子，共 9 个 checkpoint 检查：

- 配对配置、训练归一化尺度、初始损失一致。
- Staged 与 Primal–Dual 的第一阶段已保存指标逐点一致。
- 所有记录均为 4000 次模型更新、4000 次 backward、128000 个训练 prompt。

另外，从三种方法各自的 seed11 checkpoint 重新生成 256 个 ID 与 256 个 OOD 测试任务，在 `n=32` 下复算三步 recursive、teacher-forced 与差值指标。与原 CUDA 评估记录近似一致，所有复算指标的最大绝对差约为 `0.000625`，没有改变这些方法在相应指标上的排序。此次是 CPU 跨平台数值复评，不是逐位一致性证明，也不是重新训练并复现全部曲线。

机器可读结果：[report.json](../runs/implementation_audit/report.json)。可重复的主要审计脚本：[audit_training_protocol.py](../runs/implementation_audit/audit_training_protocol.py)。脚本依赖原磁盘实验文件；运行方式为在项目根目录执行 `PYTHONPATH=. python runs/implementation_audit/audit_training_protocol.py`。脚本中的梯度探针是审计计算，不计入正式实验的训练成本。

## 4. 发现的限制与学习程度诊断

### 4.1 验证集尚未实现

当前训练配置有 `val_size`，但 `run_method` 只构建训练池，没有创建和使用独立验证集。这是完整实验协议的缺口，不是现有训练目标与 checkpoint 选择规则的错误；文档明确按训练池指标选择当前输出。后续超参数研究应补充验证集，不能用测试集选择参数。

当前 `main_budget_4000` 也没有固定惩罚组，不能验证研究笔记提出的固定与自适应约束权重比较。磁盘中的其他 suite 需另行核对协议，不能直接合并结果。

### 4.2 训练模式管理有隐患，但未影响本轮检查中的当前配置

评估函数会调用 `model.eval()`，随后训练函数没有显式恢复 `model.train()`。当前模型 dropout 为零且没有 BatchNorm；在实际模型和样本上的梯度启用检查中，train/eval 模式的输出差异与参数梯度差异均为零。因此，这不是已确认的当前排名原因，但若以后引入 dropout 等依赖训练模式的模块，必须处理训练模式恢复。

### 4.3 第一步未超过不使用 demonstrations 的解析基线

由任务分布，给定 query 输入 `x`、不观察 demonstrations 时，每个第一步坐标的条件均值为

`E[ReLU(w^T x) | x] = ||x|| / (2*sqrt(pi))`，其中 `w ~ N(0, I/2)`。

因此可构建四个坐标均为该值的简单预测器。它不使用测试 query 的真实标签，也不使用 demonstrations，仅利用已知任务分布。在同一批测试任务上，其 Step 1 风险与已有三种子均值如下：

| 方法或基线 | ID Step 1，n=32 | OOD Step 1，n=32 |
|---|---:|---:|
| 无示例条件均值基线 | 7.140 | 29.136 |
| Uniform | 7.372 | 32.801 |
| Staged | 7.369 | 32.209 |
| Primal–Dual | 7.405 | 31.841 |

在固定训练池上，该基线的归一化第一步误差约为 `0.6843`，也低于当前模型最终约 `0.694–0.697` 的数值。

这提示应先研究第一步的模型容量、优化充分程度和上下文利用情况。它不证明模型完全忽略示例，也不能直接作为当前有限宽网络类全局最优值的证书；解析基线与网络模型类不同。后续可比较正确任务示例、打乱任务对应关系的示例与无信息示例，识别模型实际如何使用上下文。

## 5. 冲突二次问题检查与结果解释

另用同一套训练循环检查可解析的标量问题：

`e1(theta)=e2(theta)=(theta-1)^2`，`e3(theta)=4(theta+1)^2`。

此时无约束 `f3` 的解析最优点为 `theta=-1/3`。使用该检查自己的学习率 `0.02` 和 `200+200+2000` 更新配置，Uniform 与 Staged 的末点均到达该解析点附近；Primal–Dual 显著改变了前层保护与最终目标之间的取舍，所选输出满足约 `0.02` 的参考阈值。但其最后迭代点 `f1≈0.0893`，仍高于阈值，符合有限正则化与实际迭代不提供逐步硬可行性的限制。

该算例只检查训练循环是否能反映明确的目标冲突，不能证明神经实验中应当出现同样的优势，也没有证明 Primal–Dual 求得了精确约束最优解。其可行所选点在本次检查中是最终阶段起点，不能将这一事实包装成约束优化效率的成功验证。算例参数与结果保存在上述 `report.json` 的 `conflicting_quadratic` 字段。

无约束与约束问题本身的关系是

`min_{theta 可行} f3(theta) >= min_theta f3(theta)`。

因此，不能期待 Primal–Dual 必然获得更低训练 `f3`。Staged 最后也优化同一个 `f3`，其可能优势主要在有限预算下的优化路径或泛化，而不是存在一个必定更低的训练目标最优值。测试集优势需要由数据验证，不能作为实现正确性的判据。

## 6. 结论与后续优先级

当前更有依据的判断是：三种方法的核心实现通过了本轮静态与运行核验，尚未发现足以解释当前排名的明显算法接线错误；完整协议仍有缺口，模型第一步的学习程度也需要进一步诊断。此前仅凭曲线和静态阅读便推测原因的证据强度，低于本轮核验，不能视为已经确认的机制。

后续宜先补充简单基线与上下文利用对照，再从相同第二阶段 checkpoint、相同 Adam 初始状态和数据顺序出发，比较纯 `f3` 与 Primal–Dual 更新，并记录逐步 minibatch 残差和乘子反馈。若需要调整预算或超参数，应通过独立验证集选择，并在各方法间公开一致的选择规则。
